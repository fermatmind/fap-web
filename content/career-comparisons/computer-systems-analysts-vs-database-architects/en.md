# Computer Systems Analysts vs. Database Architects on a Returns Feature

## Where responsibilities differ

Computer systems analysts study how users work and where their systems fall short. Database architects define the structures needed to represent and retrieve business information. A partial return can expose a gap in the workflow, the model, or both.

## Compare the handoffs

| Deliverable | Computer Systems Analysts | Database Architects |
|---|---|---|
| Example | Return workflow, roles, and acceptance cases | Data model, constraints, and migration assumptions |

## One project in practice

A fictional store wants an application to handle partial returns. The analyst confirms approval steps, retry behavior and customer notifications with staff. The architect decides how a return refers back to the original order line and how cumulative quantities can be checked. They use the same return case to validate the workflow and the model.

## How to prepare

O*NET classifies computer systems analysts as work that generally requires considerable preparation. [O*NET Job Zone](https://www.onetonline.org/link/summary/15-1211.00#JobZone) BLS describes a bachelor’s degree in computing or a related field as typical for database architects. [BLS occupational preparation](https://www.bls.gov/ooh/computer-and-information-technology/database-administrators.htm#tab-4) Job Zones describe a broad level of preparation. Ask the employer which education, training and experience count for the specific job.

For systems analysis, interview users of a teaching application and write acceptance scenarios. For architecture, propose two models for the same need and explain what each makes easier to verify. Ask how the potential employer evaluates requirements and designs.

## Questions for an employer

Analysts schedule time with staff to understand actual work. Architects coordinate design review and account for records that were created before a change. Ask the analyst team who resolves conflicting user needs. Ask the database team who approves model changes and how it plans for existing records.

## Skills that transfer

To move toward architecture, extend a workflow case into a model with constraints and migration assumptions. To move toward systems analysis, start with a model and explain which actual users and decisions its design must support.

## Try it in 30 minutes

A fictional order has three units of item A. A return of two has been approved, and the customer requests two more. Spend fifteen minutes describing what staff and the customer should see, ten mapping the order line and both requests, and five writing an acceptance case that keeps the new request from being treated as approved.
