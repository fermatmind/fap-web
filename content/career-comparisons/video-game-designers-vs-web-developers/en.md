# Video Game Designers vs Web Developers

## Decide how the game plays or make it work in a browser

Video game designers specify challenges, feedback, and game rules, and use playtests to revise them. Web developers implement web pages, interactive behavior and data connections, and test how the result runs. In a browser game, a gameplay rule gives the developer something concrete to implement and verify.

## Two work samples to compare

| Item | Video game designers | Web developers |
| --- | --- | --- |
| Example team | Gameplay or level team at a game studio | Web engineering team at a product company or agency |
| Typical output | Rules, prototype, and playtest notes | Working site or application, source code, and test results |
| Portfolio evidence | A rule revised after observing a player | A feature that works across specified browsers and recovers from a failure |

## A retry rule and a browser issue in the same prototype

In a fictional browser puzzle, playtesters think the Retry button will erase a clue they already earned. The game designer decides the clue should persist, writes the intended behavior, and asks the playtest lead to check whether players understand it. The web developer finds that refreshing can trigger the retry twice in the test build. They implement the agreed state behavior, fix the duplicate action, and give the technical reviewer tests for retry and refresh recovery.

## Prepare for the particular U.S. role

O*NET places video game designers in Job Zone Four, a category for occupations that generally need considerable preparation and often a bachelor's degree. For gameplay openings, show a small prototype, an observed player difficulty, and the change you made. BLS reports that education for web development and digital design varies and that work or projects can demonstrate ability. Bring a working web feature with a reproducible test and check the degree and tool requirements in the posting. [O*NET Job Zone](https://www.onetonline.org/link/summary/15-1255.01#JobZone) · [BLS entry paths](https://www.bls.gov/ooh/computer-and-information-technology/web-developers.htm#tab-4)

## Ask who decides revisions and who supports releases

For game design, ask how often the team sees playtest feedback and how changes are agreed with engineering and art. For web development, ask which browsers the team supports, who reviews releases, and whether you respond to problems after deployment.

## Carry a prototype into the other role

A designer moving toward web development can turn a gameplay flow into browser states with test cases, then learn HTML, CSS, JavaScript, and debugging. A developer moving toward design can take an interaction they built, turn it into a paper level, and explain why they would change a rule after observing a test player.

## Try a 30-minute retry exercise

Use a fictional state card: clue A is earned, one attempt is wrong, and the player refreshes. Spend eight minutes defining the problem, twelve making either a three-panel rule sketch or a browser acceptance checklist, and ten checking normal retry and recovery after refresh. Clue A should still appear and one retry should count only once. Note which work product you would prefer to refine.
