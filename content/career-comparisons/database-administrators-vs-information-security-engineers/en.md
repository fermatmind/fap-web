# Database Administrators vs. Information Security Engineers on Reporting Access

## The responsibilities

Database administrators manage access and operation in a particular database. Information security engineers design and evaluate safeguards that can be applied consistently. A reporting project can require somebody to define how a control is tested and somebody to implement the approved change safely.

## Compare the handoffs

| Deliverable | Database Administrators | Information Security Engineers |
|---|---|---|
| Example | Access change record and checks before and after implementation | Control design, verification cases and a path for exceptions |

U.S. occupational task sources · [O*NET 15-1242.00](https://www.onetonline.org/link/summary/15-1242.00#Tasks) · [O*NET 15-1299.05](https://www.onetonline.org/link/summary/15-1299.05#Tasks)

## How the work meets

A fictional company wants teams to see only the reporting data they need. The security engineer works with data and business owners to define which access should remain and what successful verification looks like. The administrator checks the proposed roles and scheduled reports in a test setting, documents the effect on users, and gives the project owner the information needed to schedule the change.

## Build an entry example

BLS describes a bachelor’s degree in computing or a related field as typical for database administrators. Look for roles that give supervised experience in database operations and recovery. [BLS database administration](https://www.bls.gov/ooh/computer-and-information-technology/database-administrators.htm#tab-4)

To prepare for database administration, demonstrate service and recovery checks in a teaching database. To prepare for security engineering, create a fictional role matrix and show how you would verify the policy. Ask employers who owns design, implementation and review.

O*NET puts information security engineers in a category that generally requires considerable preparation. The category describes a broad level of preparation. [Information Security Engineers Job Zone](https://www.onetonline.org/link/summary/15-1299.05#JobZone) Look for supervised work with systems operations or security controls. Learn to document approved access requirements, evaluate controls in a test environment, and report effects on authorized users.

## What to ask an employer

Ask database teams who approves production access and how exceptions are recorded. Ask security engineers how teams verify a control after release and who addresses problems for legitimate users.

## Skills that transfer

Move toward security engineering by extracting a reusable rule and verification case from an access project. Move toward administration by expanding control designs into a record of runtime checks and recovery steps.

## Try it in 30 minutes

Use a fictional report, three roles, and one temporary permission. Spend ten minutes specifying allowed and denied actions, ten preparing change verification, and ten deciding who will review the temporary permission after it expires.
